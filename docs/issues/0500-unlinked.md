# 0500 결제 SQL에서 아직 연결하지 못한 부분

작성일: 2026년 11월 24일 (한국시간)

`0500_payments.sql`과 `0501_reviews.sql`은 저장소에만 있고, 공용 데이터베이스에는 실행하지 않았습니다. 아래가 없어서 실행하면 중간에 실패합니다. 나중에 4번 계약 표가 생기면 이 목록대로 한 번에 맞추면 됩니다. SQL 문장은 그때까지 고치지 않습니다.

## 1. 계약 표가 없습니다

4번 파일 `supabase/migrations/0400` 이 아직 없습니다. 공용 데이터베이스에도 `contracts` 표가 없습니다.

0500과 0501이 기대하는 칸은 아래뿐입니다. 이름과 뜻이 같으면 그대로 연결됩니다.

| 칸 | 쓰는 곳 | 기대하는 값 |
| --- | --- | --- |
| `id` | 결제·리뷰의 `contract_id` | 계약 한 건의 번호 |
| `project_id` | 결제 완료, 납품, 리뷰 | 그 계약의 프로젝트 번호 |
| `client_id` | 결제 시작, 승인, 완료 승인 | 의뢰인 프로필 번호 |
| `freelancer_id` | 납품 요청, 알림, 리뷰 | 프리랜서 프로필 번호 |
| `agreed_amount` | 결제 금액 | 원 단위 숫자. 1 이상 |
| `status` | 결제 시작 조건 | 서명이 끝난 계약은 `signed` |
| `deleted_at` | 지워진 계약 제외 | 비어 있으면 살아있는 계약 |

연결 후 확인할 동작:

- 계약이 `signed` 이고 프로젝트가 `contract_pending` 일 때만 결제가 시작됩니다.
- 결제 금액은 화면 입력이 아니라 `agreed_amount` 를 그대로 씁니다.
- 리뷰는 그 계약의 의뢰인과 프리랜서만, 서로를 대상으로 한 번씩 씁니다.

## 2. 알림 함수가 공용 데이터베이스에 없습니다

0500은 결제 완료, 납품 요청, 완료 승인 때 `public.create_notification` 을 호출합니다. 이 함수는 3번 파일 `0301_notifications.sql` 에 있습니다. 파일은 저장소에 있지만 공용 데이터베이스에는 아직 실행하지 않았습니다.

나중에 순서는 `0300` → `0301` → `0400` → `0500` → `0501` 입니다. 0301보다 0500을 먼저 실행하면 알림 함수가 없다고 실패합니다.

알림 종류는 이미 3번 표 정의에 들어 있습니다. 새로 만들 이름은 없습니다.

- `payment_completed`
- `delivery_requested`
- `delivery_approved`
- `review_requested`

## 3. 이미 연결할 수 있는 것

프로젝트 표 `projects` 는 공용 데이터베이스에 있습니다. 0500이 바꾸는 상태 이름도 그 표에 이미 있습니다.

- 결제 완료 → `in_progress`
- 납품 요청 → `delivered`
- 완료 승인 → `completed`

이 부분은 4번 표를 기다리지 않아도 이름만 맞습니다. 다만 0500 파일 전체가 계약 표를 먼저 만들기 때문에, 프로젝트 부분만 따로 실행하지는 않습니다.
