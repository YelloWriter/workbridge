# 4번 기능 명세: AI 참고 견적·금액 합의·계약·서명

작성일: 2026-11-25. 기준: `docs/TEAM.md`, `docs/rea/4-ai-contract.md`, `docs/decisions/2026-11-25-4-amount-agreement.md`.
브랜치: `feat/4-ai-contract`. 3번 지원 화면과 SQL은 고치지 않습니다.

세부 구현은 `docs/specs/4-ai-contract-detail.md` 입니다. 이 문서는 동작 약속입니다. 표는 `0400`, `0401`, 참고 견적 저장은 `0402`, 동의·거부·서명은 `0403` 입니다. 화면은 `/contracts` 와 `/contracts/[id]` 입니다.

## 화면

| 주소 | 누가 | 하는 일 |
| --- | --- | --- |
| `/ai-estimate/[projectId]` | 그 프로젝트의 의뢰인 | 저장된 설명으로 기능별 참고 견적을 만들고 다시 봅니다. 화면에 참고 금액이라고 적고, 합의 금액과 구분합니다. "예산에 반영"은 프로젝트 예산만 바꿉니다 |
| `/contracts` | 로그인한 의뢰인 또는 프리랜서 | 내가 당사자인 계약 목록. 프리랜서는 아직 계약서가 없는 수락 건에서 동의 또는 거부. 의뢰인은 그 건이 동의 대기 중이라고 봅니다 |
| `/contracts/[id]` | 그 계약의 의뢰인과 프리랜서 | 당사자, 프로젝트, 합의 금액, 시작일, 종료일, 서명 상태. `signing` 이고 내가 아직 서명하지 않았으면 서명 버튼 |

다른 사람의 주소로 들어가면 "이 계약을 볼 수 없습니다"만 보여 줍니다. 금액은 보여 주지 않습니다.

의뢰인이 금액을 입력하는 화면은 3번의 `/projects/[id]/applicants` 입니다. 4번 화면에 금액 입력칸을 만들지 않습니다. 3번이 저장한 `accepted_agreed_amount` 를 그대로 보여 줍니다.

## 입력과 출력

| 동작 | 입력 | 성공하면 돌려주는 값 | 화면에 보이는 결과 |
| --- | --- | --- | --- |
| 참고 견적 저장 | 프로젝트 id. 설명·금액은 브라우저가 보내지 않고, 저장된 설명과 검사에 통과한 응답만 씁니다 | 저장 후 같은 화면 | 기능명, 설명, 예상 단가, 산정 근거, 전체 총액 |
| 예산에 반영 | 프로젝트 id | 없음. 예산이 바뀐 같은 화면 | `projects.budget` 만 최근 참고 총액으로 바뀜 |
| 금액 동의 | 지원 id | 계약 id | 계약서 화면으로 이동합니다. 상태는 서명 중 |
| 금액 거부 | 지원 id | 지원 id | 합의가 깨졌다는 안내. 프로젝트는 다시 모집 중 |
| 서명 | 계약 id | 계약 id | 내 서명 시각이 보입니다. 양쪽이 끝나면 체결 |

금액, 시작일, 종료일은 동의 함수가 정합니다. 브라우저가 보낸 금액이나 날짜는 쓰지 않습니다.

- 합의 금액 = 그 지원의 `accepted_agreed_amount`
- 시작일 = 동의한 시각의 한국 날짜
- 종료일 = 시작일에 `applications.proposed_days` 를 더한 날짜

계약서에 보이는 내용은 이 칸뿐입니다. 당사자 이름, 프로젝트 제목, 합의 금액, 시작일, 종료일, 의뢰인 서명 시각, 프리랜서 서명 시각. 별도 파일로 저장하지 않습니다.

참고 견적 `items` 한 칸은 `name`(기능명, 1~80자), `description`(1~400자), `unit_price`(원, 정수, 10,000~500,000,000), `basis`(산정 근거, 1~300자)입니다. 기능은 1~12개입니다. `total_amount` 는 단가를 모두 더한 값과 같아야 하고, 10,000원 이상 999,999,999,999원 이하입니다. 소수, 0원, 음수, 빈 칸, 합계가 다른 응답은 저장하지 않습니다. 화면에는 "다시 시도"만 보여 줍니다.

## 서버 동작

브라우저가 `ai_estimates` 나 `contracts` 에 직접 넣거나 고치지 않습니다. 참고 견적 저장은 `save_ai_estimate` 하나만 호출합니다. 예산 반영은 의뢰인 본인의 프로젝트 수정 권한으로 `projects.budget` 만 바꿉니다. 계약처럼 여러 표를 같이 바꾸는 일은 함수 하나로 처리하고, 중간에 실패하면 함께 되돌아갑니다.

`save_ai_estimate` 는 `0402` SQL에 있습니다. 동의·거부·서명은 `0403` 의 `agree_contract_amount`, `decline_contract_amount`, `sign_contract` 입니다. 수락 화면의 금액 입력은 3번의 `accept_application(p_application_id, p_agreed_amount)` 를 그대로 씁니다. `0400`, `0401` 은 표와 조회 권한만 가지고 있어 다시 만들지 않습니다.

| 함수 | 누가 호출 | 확인하는 것 | 성공 시 |
| --- | --- | --- | --- |
| `save_ai_estimate` | 그 프로젝트의 의뢰인 | 프로젝트가 있고 지워지지 않았는지, 호출자가 `projects.client_id` 인지, 기능 목록과 총액이 위 규칙을 지키는지 | 참고 견적 한 줄을 새로 넣습니다. 규칙을 어기면 넣지 않습니다. 예전 견적 내용은 고치지 않습니다 |
| `applyEstimateToBudget` (서버 동작, DB 함수 아님) | 그 프로젝트의 의뢰인 | 최근 참고 견적이 있는지, 상태가 `scheduled` 또는 `recruiting` 인지, 모집 기간이 남았는지, 지원자가 없는지 | `projects.budget` 만 최근 `total_amount` 로 바꿉니다. 지원·계약 금액·프로젝트 상태는 그대로입니다 |
| `agree_contract_amount` | 선정된 프리랜서 | 프로젝트가 `contract_pending`, 지원이 `accepted`, 금액이 1원 이상, 살아있는 계약이 아직 없는지 | 계약을 `signing` 으로 만듭니다. 의뢰인에게 `amount_agreed` |
| `decline_contract_amount` | 선정된 프리랜서 | 위와 같고, 아직 계약이 없는지 | 프로젝트를 `recruiting` 으로, 그 지원을 `rejected` / `negotiation_failed` 로 바꿉니다. 의뢰인에게 `amount_declined` |
| `sign_contract` | 그 계약의 의뢰인 또는 프리랜서 | 상태가 `signing` 이고 내 서명 시각이 비어 있는지 | 내 서명 시각을 기록합니다. 양쪽이 채워지면 같은 호출에서 `signed` 로 바꿉니다 |

프로젝트 행을 먼저 잠급니다. 동의와 거부가 동시에 들어와도 하나만 성공합니다.

같은 지원으로 동의를 다시 호출하면 이미 만든 계약 id를 그대로 돌려주고, 계약과 알림을 새로 만들지 않습니다. 같은 사람이 서명을 다시 눌러도 서명 시각은 바뀌지 않고, 체결 알림도 다시 만들지 않습니다.

거부가 성공한 뒤의 동의, 체결된 계약의 거부, 상대방 서명 시각을 바꾸는 호출은 실패합니다.

알림은 3번의 `create_notification` 을 같은 데이터베이스 작업 안에서 보냅니다. 화면이 알림을 따로 보내지 않습니다. 수락으로 금액이 저장되면 프리랜서에게 `amount_proposed` (`/contracts`). 동의하면 의뢰인에게 `amount_agreed`, 거부하면 의뢰인에게 `amount_declined`, 양쪽 서명이 끝나면 양쪽에게 `contract_signed`. 이동 주소는 동의와 체결은 `/contracts/` 와 계약 id, 거부는 `/projects/` 와 프로젝트 id 와 `/applicants` 입니다.

## 권한

| 누구 | 참고 견적 조회 | 계약 조회 | 참고 견적 저장 | 동의·거부 | 서명 |
| --- | --- | --- | --- | --- | --- |
| 그 프로젝트 의뢰인 | 가능 | 자신의 계약만 | 가능 | 불가 | 의뢰인 서명만 |
| 선정된 프리랜서 | 불가 | 자신의 계약만 | 불가 | 가능 | 프리랜서 서명만 |
| 다른 회원 | 불가 | 불가 | 불가 | 불가 | 불가 |
| 로그인하지 않은 사람 | 불가 | 불가 | 불가 | 불가 | 불가 |
| 탈퇴한 계정 | 불가 | 불가 | 불가 | 불가 | 불가 |

조회는 `0400`, `0401` 의 RLS가 막습니다. 저장과 상태 변경은 함수만 할 수 있습니다. 프로젝트 상태를 화면이 직접 바꾸면 2번이 막아 둔 검사에서 거절됩니다. 그래서 모집 중으로 되돌리는 일도 거부 함수 안에서만 합니다.

비밀 키는 서버 환경 변수만 씁니다. `NEXT_PUBLIC_` 에 넣지 않습니다. 참고 견적 호출은 서버의 `OPENAI_API_KEY` 만 사용합니다. 키는 `gpt-4o-mini` 호출에만 쓰고, 응답은 저장 전에 zod로 다시 검사합니다.

## 부수 효과

동의가 성공하면 같이 일어나는 일입니다.

- `contracts` 에 한 줄이 생깁니다. `agreed_amount` 는 수락 금액과 같습니다.
- 프로젝트는 `contract_pending` 그대로입니다. 작업 중으로 바꾸는 일은 5번 결제입니다.
- 의뢰인에게 금액 합의 알림이 하나 갑니다.

거부가 성공하면 같이 일어나는 일입니다.

- 계약 줄은 만들지 않습니다.
- 프로젝트는 `contract_pending` 에서 `recruiting` 으로 돌아갑니다.
- 선정된 지원만 `rejected` 와 `negotiation_failed` 가 됩니다.
- `auto`, `manual`, `closed` 로 이미 거절된 지원의 이유와 상태는 그대로입니다.
- 의뢰인에게 합의 결렬 알림이 하나 갑니다.

서명이 성공하면 같이 일어나는 일입니다.

- 호출한 사람의 서명 시각만 채워집니다.
- 한쪽만 서명했으면 상태는 `signing` 입니다. 알림은 없습니다.
- 양쪽 서명이 채워지면 상태가 `signed` 가 되고, 의뢰인과 프리랜서에게 체결 알림이 각각 하나 갑니다.
- 금액, 시작일, 종료일, 이미 기록된 서명 시각은 바뀌지 않습니다.

참고 견적을 저장해도 지원 금액, 수락 금액, 계약 금액, 프로젝트 예산, 프로젝트 상태는 바뀌지 않습니다. 예산은 "예산에 반영"을 눌렀을 때만 바뀝니다.

## 시연

붙여 넣을 프로젝트 설명 3개와, 다른 계정으로 남의 계약서가 보이지 않는지 확인한 결과는 `docs/sprints/2026-11-25-4-validation.md` 에 있습니다.

## 이번 주에 만들지 않는 것

매니저, 미팅 예약, 금액 재제안, 플랫폼 서명, 도장 이미지, 종이 계약, 분할 지급, 선금, 부가세, 원천징수, 지식재산·비밀유지·하자·분쟁 조항 문장.

## 다른 담당에게

3번에게 요청하지 않고 넘어가는 부분입니다. 수락 화면의 금액 입력과 `accept_application` 은 그대로 둡니다. 4번이 그 금액에 대한 동의와 거부를 맡습니다.

2번에게 요청할 연결입니다. `src/components/projects/project-form.tsx` 는 2번 파일이라 4번이 고치지 않습니다. 예산 옆 `data-slot="ai-estimate-button"` 안의 버튼을 아래로 바꿔 주세요.

```tsx
import { AiEstimateButton } from "@/components/ai/estimate-button";

<div data-slot="ai-estimate-button">
  <AiEstimateButton />
</div>
```

등록 화면(`/projects/new`)에는 아직 프로젝트 번호가 없어서 버튼이 눌리지 않고, "등록한 뒤 수정 화면에서 눌러 주세요"라고 안내합니다. 수정 화면(`/projects/[id]/edit`)에서는 같은 버튼이 `/ai-estimate/[id]` 로 이동합니다. 결과 화면의 "예산에 반영"은 2번의 예산 수정과 같이, 지원자가 있거나 모집이 끝나면 예산을 바꾸지 않습니다.

5번은 계약이 `signed` 이고 프로젝트가 `contract_pending` 일 때 결제를 시작합니다. 동의만 된 `signing` 상태에서는 결제가 시작되지 않습니다.
