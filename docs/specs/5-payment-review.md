# 5번 기능 명세: 결제·정산·리뷰

화면 흐름의 참고는 `docs/rea/5-payment-review.md`. 금액 계산은 `docs/decisions/2026-11-24-payments.md`. 표는 `supabase/migrations/0500_payments.sql`, `0501_reviews.sql`.

이 문서는 기능 범위입니다. 파일 이름, 함수 입력, 오류 코드 같은 구현 세부는 `docs/specs/5-payment-review-detail.md` 에 있습니다.

## 쓰는 사람

- 의뢰인: 테스트 결제, 납품 확인, 프리랜서 리뷰
- 프리랜서: 납품 요청, 정산 내역 보기, 의뢰인 리뷰
- 로그인하지 않은 사람: 공개 프로필의 평균 별점과 리뷰 목록만 봄

결제는 토스페이먼츠 **테스트 키**만 씁니다. `live_` 로 시작하는 라이브 키는 쓰지 않습니다. 실제 돈이 빠져나갑니다.

## 키를 넣는 곳

1번이 보낸 Supabase 값과, 아래 토스 테스트 키를 내 컴퓨터의 `.env.local` 에 넣습니다. GitHub와 단톡방에는 올리지 않습니다.

| 변수 | 어떤 키 | 어디 두나 |
| --- | --- | --- |
| `NEXT_TOSS_CLIENT_KEY` | `test_ck` 또는 `test_gck` 로 시작 | 서버가 읽어 결제창에 넘길 때. `NEXT_PUBLIC_` 는 붙이지 않음 |
| `TOSS_SECRET_KEY` | 같은 세트의 `test_sk` 또는 `test_gsk` | 서버에서 승인을 확인할 때. `NEXT_PUBLIC_` 를 붙이지 않음 |

두 키는 개발자센터에서 나란히 있는 한 세트여야 합니다. 서로 다른 세트를 섞거나 테스트 키와 라이브 키를 섞으면 결제가 거절됩니다.

발급 순서는 이 명세 맨 아래에 있습니다.

## 화면

| 주소 | 누가 | 하는 일 |
| --- | --- | --- |
| `/payments/[contractId]` | 그 계약의 의뢰인, 프리랜서 | 금액, 수수료 10%, 정산액, 현재 상태. 의뢰인은 테스트 결제 버튼. 프리랜서는 작업 중일 때 납품 요청. 의뢰인은 납품 요청 상태일 때 완료 승인 |
| `/payments/success` | 결제를 막 마친 의뢰인 | 토스가 돌려보낸 값을 서버로 넘기고, 성공이면 안내 후 내역으로 이동 |
| `/payments/fail` | 결제가 취소되거나 실패한 의뢰인 | 실패를 기록하고 다시 결제할 수 있다고 안내 |
| `/payments/history` | 로그인 사용자 | 내가 당사자인 결제만 목록 |
| `/reviews/new/[contractId]` | 완료된 계약의 당사자 중 아직 안 쓴 사람 | 별점, 내용, 태그 작성 |
| `/users/[id]` 의 리뷰 자리 | 누구나 | 평균 별점, 개수, 그 사람이 받은 리뷰. 1번이 비워 둔 `data-slot="public-reviews"` 안에 5번 컴포넌트를 넣음 |

다른 계약의 결제 주소로 들어가면 "이 계약을 볼 수 없습니다"만 보여 줍니다. 금액은 보여 주지 않습니다.

## 돈이 움직이는 순서

1. 계약이 `signed` 이고 프로젝트가 `contract_pending` 일 때 의뢰인이 결제를 시작합니다. `payments` 한 줄이 `ready` 로 생깁니다. 주문번호는 `wb_` 로 시작합니다.
2. 브라우저가 토스 테스트 결제창을 엽니다. 금액은 서버가 적어 둔 `amount` 만 씁니다.
3. 토스가 `/payments/success` 로 `paymentKey`, `orderId`, `amount` 를 돌려줍니다.
4. 서버가 토스 승인 API를 시크릿 키로 호출합니다. 승인 금액이 우리 `amount` 와 같을 때만 `mark_payment_paid` 를 호출합니다.
5. 상태가 `paid` 가 되고 `approved_at` 이 찍힙니다. 프로젝트는 `in_progress` 가 됩니다. 프리랜서에게 `payment_completed` 알림이 갑니다.
6. 프리랜서가 납품 요청을 하면 프로젝트는 `delivered`, 의뢰인에게 `delivery_requested` 알림이 갑니다. 돈은 아직 `paid` 입니다.
7. 의뢰인이 완료 승인을 하면 프로젝트는 `completed`, 결제는 `paid_out`, `paid_out_at` 이 찍힙니다. 프리랜서에게 `delivery_approved`, 양쪽에게 `review_requested` 알림이 갑니다.

실패 화면에서는 `ready` 인 결제만 `failed` 로 바꿉니다. 그 계약은 의뢰인이 다시 결제를 시작할 수 있습니다. `paid` 인 돈을 실패로 바꾸지는 않습니다.

## 금액

| 칸 | 뜻 |
| --- | --- |
| `amount` | 의뢰인이 내는 계약 금액 |
| `fee_amount` | `amount` 의 10%에서 1원 미만은 버린 수수료 |
| `payout_amount` | 프리랜서에게 확정되는 금액. `amount - fee_amount` |

화면에는 세 수를 모두 보여 줍니다. 수수료를 화면에서 입력받지 않습니다.

## 서버 동작

모두 데이터베이스 함수입니다. 브라우저가 `payments` 나 `reviews` 에 직접 insert, update 하지 않습니다.

| 함수 | 누가 호출 | 입력 | 성공 시 |
| --- | --- | --- | --- |
| `start_payment` | 의뢰인 | 계약 id | `ready` 결제 id |
| `mark_payment_paid` | 의뢰인, 토스 승인 성공 뒤 | 주문번호, paymentKey, 금액 | `paid`, 프로젝트 `in_progress`, 알림 |
| `mark_payment_failed` | 의뢰인 | 주문번호 | `ready` 만 `failed` |
| `request_delivery` | 프리랜서 | 계약 id | 프로젝트 `delivered`, 알림 |
| `approve_delivery` | 의뢰인 | 계약 id | 프로젝트 `completed`, 결제 `paid_out`, 알림 3개 |
| `create_review` | 계약 당사자 | 계약 id, 별점 1~5, 내용, 태그 | 리뷰 id |

실패하면 함수가 이유를 담은 오류를 내고, 그때까지 바꾼 돈과 프로젝트 상태는 함께 되돌아갑니다.

알림은 3번이 만든 `create_notification` 만 사용합니다. 종류는 `payment_completed`, `delivery_requested`, `delivery_approved`, `review_requested` 입니다.

## 리뷰 입력

| 칸 | 규칙 |
| --- | --- |
| 별점 | 1, 2, 3, 4, 5 중 하나 |
| 내용 | 앞뒤 공백을 뺀 뒤 1~1000자 |
| 태그 | 소통, 일정, 품질, 전문성, 재계약 중 최대 5개. 없어도 됨 |

상대방은 자동으로 정해집니다. 의뢰인이 쓰면 프리랜서가 받고, 프리랜서가 쓰면 의뢰인이 받습니다. 화면에서 대상을 고르지 않습니다.

이미 쓴 사람은 그 주소에 다시 들어와도 수정 칸 없이 내가 쓴 내용을 보여 줍니다.

| 결제 내용 보기 | 불가 | 불가 | 자기 계약만 | 자기 계약만 |

| 리뷰 작성 | 불가 | 불가 | 완료된 자기 계약에 1회 | 완료된 자기 계약에 1회 |

## 공개 프로필에 넣는 컴포넌트

1번 페이지의 이 자리만 채웁니다. 1번 파일의 다른 부분은 고치지 않습니다.

```tsx
<div data-slot="public-reviews" data-user-id={id} />
```

보여줄 것:

- `review_summaries` 의 평균과 개수. 리뷰가 없으면 "아직 리뷰가 없습니다".
- 그 사람이 받은 리뷰. 작성자 이름, 별점, 내용, 태그, 날짜.

## 이번 주에 하지 않는 것

- 라이브 키 결제, 환불 화면, 세금계산서, 원천징수
- 부분 정산, 중도금
- 분쟁 조정

## 토스 테스트 키 받는 순서

1. https://developers.tosspayments.com 에 이메일로 가입하고 로그인합니다. 사업자 등록은 필요 없습니다.
2. 개발자센터에서 **API 키** 메뉴를 엽니다.
3. 상점이 여러 개면 **개발 연동 체험** 또는 **개발자용 테스트상점**을 고릅니다.
4. 화면 위쪽이 **테스트**인지 확인합니다. **라이브** 탭의 키는 복사하지 않습니다.
5. 클라이언트 키와 시크릿 키가 같은 줄에 있는 한 세트를 복사합니다.
   - 클라이언트 키는 `test_ck` 또는 `test_gck` 로 시작합니다. `.env.local` 의 `NEXT_TOSS_CLIENT_KEY`
   - 시크릿 키는 `test_sk` 또는 `test_gsk` 로 시작합니다. `TOSS_SECRET_KEY`
6. `live_` 로 시작하는 키가 보이면 그 칸은 비워 둡니다.
7. 파일을 저장한 뒤 개발 서버를 다시 켭니다. 이 파일은 커밋하지 않습니다.

키가 `test_gck` / `test_gsk` 만 있으면 그 세트를 쓰고, 1번에게 개인 메시지로 어떤 글자로 시작하는지 알려 주세요. `test_ck` 와 `test_gsk` 처럼 서로 다른 종류를 섞지 않습니다.
