## 1. F-01 홈 화면

**목적:** 처음 오는 사람이 바로 프로젝트를 검색하거나 카테고리로 들어가고, 최신 모집 중 프로젝트를 훑어봅니다. **주소:** `/` **쓰는 사람:** 누구나

### 화면 구성 (위 → 아래)
1. 소개 문구: "맞는 프로젝트와 맞는 사람을 안전하게 이어 드려요" + 한 줄 설명
2. **검색창** (자리 글: "어떤 프로젝트를 찾으세요? 예: 쇼핑몰, 앱, 로고") + "검색" 버튼
3. **카테고리 버튼 5개:** 웹 개발 / 앱 개발 / 디자인 / 기획 / 데이터·AI (`src/lib/constants.ts` 의 `CATEGORIES`, 1번과 같은 목록)
4. **최신 프로젝트** 제목 + "전체 보기" + "프로젝트 등록" 버튼
5. 프로젝트 카드 최대 6개(2열)

### 처리
| 동작 | 결과 |
| --- | --- |
| 검색창에 입력하고 "검색" | `/projects?q=입력값` 으로 이동 (F-04) |
| 카테고리 버튼 클릭 | `/projects?category=카테고리` 로 이동 (F-05) |
| "전체 보기" | `/projects` |
| "프로젝트 등록" | `/projects/new` (로그인·역할 확인은 F-02 에서) |
| 카드 제목 클릭 | `/projects/[id]` |

최신 프로젝트는 **모집 중**(C-01 기준) 프로젝트만, **등록한 순서가 최신인 것부터** 6개입니다.

### 오류·예외
| 상황 | 화면 |
| --- | --- |
| 모집 중 프로젝트가 하나도 없음 | "지금 모집 중인 프로젝트가 없어요. 첫 프로젝트를 등록해 보세요." |
| 조회 실패 | C-09 |

### 확인 기준
| ID | 확인할 것 | 결과 | 어떻게 확인 |
| --- | --- | --- | --- |
| F-01-A1 | 검색창이 있고 입력 칸 이름이 `q` | ○ | 가짜 데이터 화면 시험 |
| F-01-A2 | 카테고리 버튼이 5개 | ○ | 가짜 데이터 화면 시험 |
| F-01-A3 | 카테고리 버튼을 누르면 해당 카테고리 목록 주소로 이동 | ○ | 가짜 데이터 화면 시험 |
| F-01-A4 | 최신 프로젝트가 모집 중만 최대 6개 | ◎ | 팀 DB: 모집 중 2개 표시. 가짜 데이터: 6개 이하, 마감 카드 없음 |
| F-01-A5 | 홈 검색창에서 "검색"을 누르면 `/projects?q=` 로 이동 | △ | 같은 방식의 목록 화면 검색창은 확인(F-04-A1). 홈 검색창 제출 자체는 확인하지 않음 |
| F-01-A6 | 모집 중이 없을 때 안내 문구 | △ | 코드로만 확인 |

## 2. F-02 프로젝트 등록

**목적:** 의뢰인이 세 단계로 프로젝트를 올립니다. **주소:** `/projects/new` **쓰는 사람:** 로그인한 의뢰인

### 화면 구성
- 위: 단계 표시 `1. 기본 정보 · 2. 모집 조건 · 3. 기술 스택` (현재 단계 강조)
- **1단계:** 제목, 프로젝트 설명, 카테고리
- **2단계:** 모집 시작일, 모집 마감일, 예산(원) + 예산 칸 옆 **"AI 단가 분석" 버튼 자리**(지금은 눌리지 않는 버튼, `data-slot="ai-estimate-button"`, 4번이 연결) + 입력한 금액을 읽기 쉽게 보여 주는 한 줄
- **3단계:** 필요한 기술 스택(최대 10개) — `SKILLS` 14개를 둥근 버튼으로 선택
- 아래: "이전" / "다음"(1·2단계) / "프로젝트 등록"(3단계) / "취소"(→ `/projects`)

### 입력 규칙
| 칸 | 규칙 | 어기면 나오는 문구 |
| --- | --- | --- |
| 제목 | 필수, 2~100자 | 제목은 2~100자로 입력해 주세요. |
| 프로젝트 설명 | 필수, 10~5,000자 | 설명은 10~5,000자로 입력해 주세요. |
| 카테고리 | 필수, `CATEGORIES` 중 하나 | 카테고리를 선택해 주세요. |
| 기술 스택 | 0~10개, 목록(`SKILLS`)에 있는 것만 | 기술 스택은 목록에서 최대 10개까지 고를 수 있습니다. |
| 예산 | 필수, 0 이상 정수(원), 최대 999,999,999,999 | 예산은 0 이상의 숫자(원 단위)로 입력해 주세요. |
| 모집 시작일·마감일 | 필수, 날짜 형식 | 모집 시작일과 마감일을 선택해 주세요. |
| 마감일 ≥ 시작일 | 같은 날 가능 | 모집 마감일은 시작일보다 같거나 뒤여야 합니다. |
| 마감일 ≥ 오늘 | 등록할 때만 | 모집 마감일은 오늘 이후로 정해 주세요. |

### 단계 이동 동작
- "다음"을 누르면 **그 단계의 입력만** 브라우저가 검사하고, 통과해야 다음 단계로 갑니다. 이전 단계 값은 그대로 남습니다.
- 1·2단계에서 입력 칸에서 **Enter 를 누르면 저장하지 않고 다음 단계**로 갑니다.
- 시작일 기본값은 오늘, 시작일 최소값은 오늘, 마감일 최소값은 시작일.

### 처리 순서 (서버 동작 `createProject`)
1. 로그인 확인 → 없으면 `/login?next=/projects/new`
2. 역할 확인 → 역할이 없으면 `/onboarding/role?next=/projects/new`, 프리랜서면 "의뢰인 계정으로 이용해 주세요."
3. **이름이 비어 있으면** `/me/profile?next=/projects/new` 로 보내고, 저장 후 돌아옴 (1번 명세의 "이름이 비어 있음" 기준)
4. 입력 검사(위 표) → 틀리면 해당 문구를 화면 아래에 표시
5. 시작일이 **오늘 이후이면 `scheduled`(모집 예정), 오늘이거나 지났으면 `recruiting`(모집 중)** 으로 저장 (TEAM.md)
6. 저장 성공 → `/projects/[새 프로젝트 번호]` 로 이동

### 오류·예외
| 상황 | 화면 |
| --- | --- |
| 저장 실패 | "프로젝트를 등록하지 못했습니다. 입력 내용을 확인하고 다시 시도해 주세요." |
| 로그인했지만 프리랜서 | 화면 안내: "프로젝트 등록은 의뢰인 계정에서 할 수 있어요. 내 프로필에서 역할을 바꿀 수 있습니다." |
| 미리보기 모드 | C-11 |

## 3. F-03 프로젝트 목록

**목적:** 모든 프로젝트를 카드로 훑어보고 정렬·페이지로 이동합니다. **주소:** `/projects` **쓰는 사람:** 누구나

### 화면 구성 (위 → 아래)
1. 제목 "프로젝트 찾기" + 설명 "모집 중인 프로젝트를 키워드와 조건으로 찾아보세요." + "프로젝트 등록" 버튼
2. 검색·필터 영역 (F-04, F-05)
3. 결과 줄: "총 N개" (2페이지부터 "· 2/3 페이지") + 정렬 선택 3개(최신순 · 마감 임박순 · 예산 높은순, 현재 정렬 강조)
4. 프로젝트 카드 목록
5. 페이지 이동

### 카드 1개
| 표시 | 내용 |
| --- | --- |
| 상태 배지 | 모집 예정 / 모집 중 / 모집 마감 (C-01), NEW(C-05), 카테고리 |
| 제목 | 누르면 `/projects/[id]` |
| 설명 | 앞 2줄 |
| 기술 태그 | 있을 때만 |
| 예산 | C-03 |
| 모집 마감 | 날짜 + 남은 기간(C-04, 모집 마감 상태에서는 남은 기간 생략) |
| 지원자 | "N명" |

### 정렬
| 선택 | 규칙 |
| --- | --- |
| 최신순 (기본) | 등록한 순서가 최신인 것부터 |
| 마감 임박순 | 마감일이 빠른 것부터. **모집 마감 상태는 맨 뒤** |
| 예산 높은순 | 예산이 큰 것부터, 같으면 최신순 |

### 페이지 이동
- **10개씩.** 번호 버튼은 현재 쪽 주변 최대 5개, 현재 쪽 강조, 첫 쪽이 아니면 "이전", 마지막 쪽이 아니면 "다음". 쪽이 1개뿐이면 이동 영역을 숨김. 쪽 번호는 1~1000.
- 정렬·필터를 바꾸면 1쪽으로 돌아갑니다.

### 목록 주소의 값 (C-06)
| 이름 | 뜻 | 올바른 값 |
| --- | --- | --- |
| `q` | 키워드 | 100자까지, 앞뒤 공백 제거 |
| `category` | 카테고리 | `CATEGORIES` 중 하나 |
| `skills` | 기술(여러 개) | `SKILLS` 에 있는 것만, 중복 제거 |

## 4. F-04 키워드 검색

**목적:** 제목이나 설명에 들어 있는 글자로 프로젝트를 찾습니다. **주소:** 홈 검색창 → `/projects?q=`, 목록 위 검색창 **쓰는 사람:** 누구나

### 규칙
- 제목 **또는** 설명에 키워드가 들어 있으면 찾습니다. 대소문자는 구분하지 않습니다.
- 키워드는 앞뒤 공백을 지우고 **100자까지**만 씁니다. 비어 있으면 키워드 조건이 없는 것으로 봅니다.
- **`%` 와 `_` 는 검색 기호가 아니라 일반 글자**로 찾습니다. (예: "100%"는 "100%"가 들어간 글만, "_"는 밑줄이 들어간 글만)
- 다른 필터(F-05)와 함께 쓰면 모두 만족하는 것만 나옵니다.
- 검색창 자리 글: "제목이나 설명에서 키워드 검색". 결과 개수는 "총 N개".

## 7. F-07 북마크

**목적:** 프리랜서가 관심 있는 프로젝트를 모아 둡니다. **주소:** 상세의 북마크 버튼, `/me/bookmarks` **쓰는 사람:** 프리랜서

### 7-1. 북마크 켜기·끄기 (상세 화면)
| 동작 | 결과 |
| --- | --- |
| "☆ 북마크" 클릭 | 북마크 저장, 버튼이 **"★ 북마크 해제"** 로 바뀜 |
| "★ 북마크 해제" 클릭 | 북마크 삭제, "☆ 북마크" 로 돌아감 |
| 새로고침 | 상태 유지 |
| 같은 북마크를 한 번 더 저장 | 오류 없이 한 번만 저장 (중복 무시) |

버튼은 누르는 동안 "저장하고 있어요…" 로 바뀌고, 눌린 상태는 보조 기술에 전달됩니다(`aria-pressed`).

### 7-2. 내 북마크 `/me/bookmarks`
- 제목 "내 북마크" + "관심 있는 프로젝트를 모아서 볼 수 있어요."
- 프로젝트 카드(F-03 과 같은 모양) + "상세" 버튼 + "★ 북마크 해제" 버튼
- **북마크한 순서가 최신인 것부터.** 삭제된 프로젝트는 보이지 않습니다.

### 처리 순서 (서버 동작 `toggleBookmark(프로젝트 번호, 켤지 여부)`)
1. 번호 형식 검사
2. 로그인 확인 → 없으면 `/login?next=/projects/[id]`, 역할이 없으면 `/onboarding/role?next=…`
3. 프리랜서인지 확인
4. 켜기: `bookmarks` 에 (내 번호, 프로젝트 번호) 저장(이미 있으면 무시) / 끄기: 그 줄 삭제
5. 홈·목록·내 북마크·그 프로젝트 화면 갱신

## 8. F-08 추천 프로젝트

**목적:** 상세를 본 사람에게 비슷한 모집 중 프로젝트를 보여 줘 더 둘러보게 합니다. **주소:** `/projects/[id]` 아래 **쓰는 사람:** 누구나

### 규칙
- 제목 "추천 프로젝트" + 설명 "같은 카테고리이거나 필요한 기술이 비슷한 모집 중 프로젝트예요."
- **후보:** 지금 보는 프로젝트와 **같은 카테고리**이거나 **기술이 하나라도 겹치는** **모집 중** 프로젝트. (각각 최근 20개씩 찾아 합침)
- **점수:** (같은 카테고리이면 2점) + (겹치는 기술 개수). **점수가 높은 순**, 같으면 최신순.
- **최대 4개**, 2열 카드. **지금 보는 프로젝트 자신은 제외.**
- 후보가 하나도 없으면 이 영역을 **통째로 숨깁니다.**
- 카드는 F-03 의 카드와 같은 모양입니다.

### 오류·예외
| 상황 | 화면 |
| --- | --- |
| 후보 없음 | 영역 없음 |
| 조회 실패 | 상세 전체가 C-09 |
