# 2026-11-24 결제 금액과 리뷰 규칙

RFP에 없는 계산 방법이라 5번이 이렇게 정했습니다. 표 이름과 상태값(`ready`, `paid`, `paid_out`, `failed`, `refunded`)은 `docs/TEAM.md` 2장을 그대로 씁니다.

## 수수료는 계약 금액의 10%

위시켓 공개 요금은 금액 구간과 등급에 따라 달라지고, 의뢰인이 부가세를 더 냅니다. 그 비율은 베끼지 않습니다. 팀 약속의 `fee_amount` 10%만 씁니다.

- `amount` 는 계약의 `agreed_amount` 와 같은 원 단위 금액입니다. 부가세를 더하지 않습니다.
- `fee_amount` 는 `amount` 를 10으로 나눈 몫입니다. 1원 단위는 버립니다.
- `payout_amount` 는 `amount - fee_amount` 입니다. 그래서 수수료와 정산액을 더하면 항상 결제 금액과 같습니다.
- 예: 100,000원이면 수수료 10,000원, 프리랜서 90,000원. 100,001원이면 수수료 10,000원, 프리랜서 90,001원.

세금계산서, 원천징수, 등급별 할인, 정부 지원 사업 예외는 만들지 않습니다.

## 돈의 상태 변경은 표에 직접 쓰지 않는다

브라우저가 `payments` 를 update 할 수 없습니다. 결제 시작, 결제 완료, 실패, 납품 요청, 완료 승인은 데이터베이스 함수로만 바뀝니다. 함수가 프로젝트 상태와 알림을 같은 작업 안에서 같이 바꿉니다. 화면이 표 두 개를 따로 고치면 돈은 보관됐는데 프로젝트는 그대로인 상태가 생기기 때문입니다.

## 리뷰는 한 번만, 완료 뒤에만

완료 승인으로 프로젝트가 `completed` 가 된 계약에서, 의뢰인과 프리랜서가 서로를 한 번씩만 평가합니다. 수정 함수는 만들지 않습니다. 태그는 소통, 일정, 품질, 전문성, 재계약 중에서만 고릅니다. 비슷한 말을 사람마다 다르게 적으면 나중에 모아서 보여 줄 수 없기 때문입니다.
