# 실시간 알림과 최종 통합 준비 결정

2026-11-24. 목~금 범위를 미리 구현·검증한 기록이며, 실서비스 배포 완료 기록이 아니다.

- 목록 자체에 실시간 구독을 둔다. 이전에는 종 컴포넌트가 목록 갱신도 담당해, 1번이 헤더에 종을 넣기 전에는 목록의 새 알림이 표시되지 않았다. 목록과 종을 독립적으로 사용할 수 있게 분리했다.
- 각 컴포넌트의 구독 이름에 인스턴스 ID를 붙인다. 한 화면의 구독 해제가 다른 화면의 구독을 끊지 않게 한다.
- 연속 이벤트는 200ms로 묶고 개수 요청은 하나씩 실행한다. 처리 도중 새 사건이 오면 오래된 결과를 버리고 다시 조회한다. 여러 건을 모두 읽음으로 바꿀 때 불필요한 요청을 줄인다.
- 연결 오류는 30초 보완 조회로 대응한다. 숨긴 탭은 주기 조회하지 않으며, 포커스·온라인 복귀·다시 보이는 시점에는 놓친 소식을 확인한다.
- 로그아웃·계정 전환은 기존 계정의 숫자와 구독을 즉시 정리한다. 늦게 도착한 이전 계정 요청 결과는 표시하지 않는다.
- 실제 1번 Header는 클라이언트 컴포넌트여서 서버 종 컴포넌트를 직접 import할 수 없다. 별도 `NotificationBellWidget`을 3번 폴더에 만들고 1번이 넣을 수 있는 인터페이스를 제공한다. 공통 헤더 파일은 수정하지 않는다.
- 실제 1번 프로필은 이름만 필수이고 나머지는 선택이다. 3번도 이 조건을 따르도록 0303에서 지원 RPC를 보완한다. 프로필을 저장해도 다시 프로필로 보내지는 순환을 방지하기 위한 변경이며 DB 이름·상태값은 바꾸지 않는다.
- 실제 키 없이 검증하기 위해 임시 auth/storage 기반 객체와 실제 팀 SQL을 사용한다. WebSocket 이벤트 전달만 대역으로 구현하고, 실제 Supabase Realtime 검증과 분명히 구분한다.
- 공용 환경 검증 스크립트는 기본 실행 시 로그인·권한 준비만 확인한다. `--run`을 지정했을 때만 식별 가능한 시연 프로젝트 3개를 만든다. 결과 JSON에는 비밀번호·JWT·키를 저장하지 않는다.

실제 배포의 공개 연결 정보를 사용한 읽기 요청은 401 Invalid API key로 거절됐다. 공개 키를 보고서나 Git에 복사하지 않았다. 정상 연결 정보 또는 Supabase 연결 권한 없이 실 DB SQL을 실행하거나 성공했다고 기록하지 않는다.
