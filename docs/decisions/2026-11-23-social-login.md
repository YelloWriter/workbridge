# 2026-11-23 소셜 로그인은 구글 하나

RFP는 "소셜 로그인 1종"만 말하고 종류를 정하지 않았습니다.

## 구글을 고른 이유

위시켓 공개 로그인에는 구글과 페이스북이 있었습니다. 카카오는 그 화면에 없었습니다.

- 구글은 Supabase 에 제공자가 들어 있어서, 구글 클라우드에서 클라이언트 ID만 만들면 연결됩니다.
- 카카오는 Supabase 기본 목록에 없어서 설정이 더 깁니다.
- 페이스북은 앱 심사와 설정이 구글보다 번거롭고, 1종만 두면 됩니다.

그래서 구글만 둡니다. 카카오나 페이스북은 이번 주에 추가하지 않습니다.

## 같은 이메일이면 계정 하나

이메일로 가입한 사람이 나중에 같은 이메일의 구글로 들어와도 **새 회원을 만들지 않습니다.** Supabase 가 인증된 이메일이 같으면 자동으로 한 사용자에 붙입니다. 끄기 스위치는 없습니다.

전제: 이번 주는 Confirm email 을 꺼 둡니다 (`docs/decisions/2026-11-23-profiles.md`). 그러면 이메일 가입도 바로 "인증됨"으로 처리되어, 같은 구글 메일이 그 계정에 붙습니다. `profiles.id` 도 그대로라서 프로젝트나 지원이 갈라지지 않습니다.

이메일이 다르면 다른 사람입니다. 로그인한 뒤에 다른 메일의 구글을 억지로 붙이는 기능(manual linking)은 켜지 않습니다.

구글로 먼저 가입한 사람이 같은 이메일로 비밀번호 가입을 다시 하면, Supabase 는 새 계정을 만들지 않고 가입을 막습니다. 화면에는 "이미 가입된 이메일입니다. 구글로 로그인해 주세요." 라고 보여 줍니다.
