## 팀 공용 환경에서 남은 실제 검증

**아래는 모두 미실행이다. 테스트 통과로 표시하지 않는다.**
필요한 것: 0100/0200 SQL, 팀 Supabase 키, 1번 인증/프로필 화면, 2번 프로젝트 화면, 의뢰인 1명·완성된 프리랜서 2명.

| 순서 | 실행 | 기대 |
| --- | --- | --- |
| 1 | 의뢰인 C가 모집 중 프로젝트 P 등록 | 프리랜서가 상세 접근 가능 |
| 2 | 프리랜서 A가 지원 | 내 지원 현황 이동, pending, C의 신규 지원 알림 |
| 3 | A가 다시 지원 | 중복 저장되지 않음 |
| 4 | 프리랜서 B가 지원 | 지원서 총 2개, C의 미확인 알림 증가 |
| 5 | C가 A를 수락하면서 협의 시작 금액 입력 | A accepted, B rejected/auto, P contract_pending, C/A/B 각각 알림 |
| 6 | A/B가 서로의 지원 ID로 접근 시도 | 상대 지원서 내용 노출 없음 |
| 7 | A/B가 알림 선택 | 본인 알림만 읽음, 내 지원 현황으로 이동, 종 개수 감소 |
| 8 | 모두 읽음 클릭 | 다른 계정의 미확인 수는 그대로 |
| 9 | 별도 프로젝트에서 B 직접 거절 후 모집 마감 | B manual 유지, 나머지 pending은 closed, 모든 지원자 마감 알림 |
| 10 | 다른 의뢰인이 P 지원자 관리 접근 | 조회·결정 불가 |
| 11 | 미완성 프로필로 지원 진입 | 프로필 완성 후 원래 지원 페이지 복귀 |
| 12 | 두 의뢰인 세션에서 다른 지원자 동시 수락 / 마감과 동시 수락 | accepted 최대 1명, 알림 중복·대기 지원 누락 없음 |
| 13 | 두 브라우저에서 한 쪽이 지원·읽음 변경 | 다른 쪽 종 숫자/알림이 Realtime으로 갱신, 단절 시 보완 조회 |
| 14 | 4번이 선정 결과로 계약 생성·합의 결렬 처리 | 저장 금액 전달, 계약 중복 없음, 거절 기록 유지 |

## 남은 주간 작업

- 화: 팀 SQL/키를 연결하고 화면의 실제 로그인·프로필 복귀·폼 동작 확인.
- 수: 가입 → 프로젝트 등록 → 지원 → 알림 통합 확인. 세 계정의 선정 시나리오 기록.
- 목: 4번 계약 인계·5번 공용 알림 연결, 실제 Realtime 확인, 시드 데이터 협의.
- 금: 최종 통합 브랜치/배포 환경 확인, 전체 시연, 회고 정리. 3번은 main에 직접 push/merge하지 않음.

## 최종 로컬 결과

- `npm run lint`: 통과 (0 오류).
- `npm run build`: 통과. TypeScript 및 페이지 생성 완료.
- 공개 환경 변수가 설정된 배포 조건도 더미 URL/anon 값으로 빌드 통과를 확인했다. 실제 서비스 접속·인증 검증은 아니다. 더미 값은 파일에 저장하지 않았다.
- 임시 PostgreSQL/PGlite DB 검사: **58개 통과**. 최신 SQL 2개를 그대로 실행했다.
- 프로덕션 서버 HTTP 검사: 4개 담당 페이지의 200 응답·연결 대기 안내를 확인했다. 잘못된 UUID의 지원/지원자 관리 주소 2개는 404 화면 표시를 확인했다. Next.js 스트리밍 특성상 이 경우 HTTP 헤더는 200이며 스트림 안에 404와 noindex가 들어간다.
- 공개 상세의 지원 버튼 위치는 브라우저 스크린샷과 접근성 트리로 확인했다. 실제 로그인 화면/지원 폼/알림 목록은 조사하지 않았다.
- **인증된 앱 UI의 브라우저 조작 검증 및 실제 세 계정 시연은 하지 못했다.** 팀 키와 선행 화면/테이블이 필요하다.
- DB 검사는 최소 팀 스키마 fixture 기준이다. 실제 0100/0200 SQL과의 조합, Supabase 호스팅 권한·Realtime, 별도 DB 연결의 진짜 동시 실행은 추가 확인이 필요하다.
