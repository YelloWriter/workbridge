# 위시켓 공개 화면 분석 (1번: 로그인·프로필)

분석일: 2026년 11월 23일 (한국시간)

참고 서비스의 **화면이 어떤 순서로 이어지는지**만 적었습니다. 문구, 숫자, 로고, 색, 이미지는 가져오지 않습니다. 로그인이 필요한 화면은 열지 않았습니다.

## 어떻게 봤나

[REA](https://github.com/morluto/rea) `rea@6.10.1` 의 브라우저 시나리오(`capture-browser-scenario`)로 공개 페이지만 열었습니다. 로그인 정보는 입력하지 않았고, 스크립트 원문이나 내부 API는 수집하지 않았습니다.

| 주소 | 결과 |
| --- | --- |
| `https://www.wishket.com/` | 공개. 메인과 헤더를 확인 |
| `https://www.wishket.com/partners/` | 공개. 파트너 목록 카드까지 확인 |
| `https://auth.wishket.com/login` | 공개. 로그인 입력 화면 |
| `https://auth.wishket.com/signup` | 공개. 회원가입 입력 화면 |
| `https://www.wishket.com/partners/p/{아이디}/` | 공개가 아님. 서버가 로그인 주소로 보냄. 여기서 멈춤 |

## 메인에서 이어지는 흐름

로그인하지 않은 사람에게 메인은 **의뢰하는 쪽**으로 안내합니다.

1. 헤더에서 프로젝트 등록, 프로젝트 찾기, 파트너 찾기, 이용 안내, 포트폴리오를 고를 수 있습니다.
2. 화면 위쪽의 가장 큰 버튼은 프로젝트 등록으로 갑니다. 그 옆 버튼은 견적 상담 신청으로 갑니다.
3. 분야 버튼(웹, 앱, AI 같은 묶음)은 프로젝트 목록으로 갑니다. 이 목록은 2번 담당입니다.
4. 검색창은 "비슷한 사례" 검색으로 갑니다. WorkBridge 범위 밖이라 따라 하지 않습니다.
5. 그 아래에 포트폴리오 카드, 자주 묻는 질문, 다시 등록으로 보내는 버튼이 있습니다.
6. 바닥글에는 의뢰인 안내와 파트너 안내가 나란히 있습니다. 역할이 둘이라는 점만 참고합니다.

WorkBridge 홈 화면 자체는 2번이 만듭니다. 1번은 헤더의 가입/로그인 진입만 맞춥니다.

## 헤더 (로그인 전)

같은 헤더가 메인과 파트너 목록에 있었습니다.

항상 보이는 묶음:

- 로고 → 메인
- 프로젝트 등록
- 프로젝트 찾기 (안에 사례 검색 링크도 있음)
- 파트너 찾기
- 이용방법 (등급, 요금, 고객센터 링크가 같이 있음)
- 포트폴리오 (이용후기 링크가 같이 있음)
- 비즈니스 솔루션 (엔터프라이즈, 스토어 링크가 같이 있음)
- **로그인**, **회원가입**

회사의 다른 서비스로 가는 링크도 헤더 맨 위에 있었습니다. WorkBridge에는 넣지 않습니다.

로그인·회원가입은 본 사이트가 아니라 `auth.wishket.com` 으로 갑니다. 주소 뒤에 `next` 가 붙고, 로그인이 끝나면 원래 보던 주소로 돌아가게 되어 있습니다.

- 메인의 회원가입 `next` 는 프로젝트 등록 쪽을 가리켰습니다.
- 파트너 목록의 로그인/회원가입 `next` 는 그 목록 주소를 가리켰습니다.

WorkBridge도 로그인 뒤 "가려던 주소"로 돌아가는 흐름을 쓰되, 주소는 우리 사이트 안의 상대 경로만 허용합니다. (결정: `docs/decisions/2026-11-23-profiles.md`)

로그인된 헤더는 보지 않았습니다. 로그인 후 메뉴는 팀 약속대로 1번이 새로 구성합니다. 위시켓 로그인 후 메뉴를 베끼지 않습니다.

## 회원가입 진입

공개 회원가입 화면의 입력 순서:

1. 이메일
2. 아이디 (이메일과 별도)
3. 비밀번호, 비밀번호 확인 (화면 안내 기준 8자 이상 32자 이하)
4. 약관 동의 (필수 1개, 선택 2개)
5. 회원가입 버튼
6. 또는 구글 / 페이스북
7. 이미 계정이 있으면 로그인으로 이동

이 화면에는 **의뢰인/프리랜서 선택이 없습니다.** 가입 뒤에 역할을 묻는지 보려면 로그인이 필요해서 확인하지 않았습니다.

WorkBridge에 가져갈 흐름:

- 이메일과 비밀번호로 가입한다.
- 약관 동의는 이번 주 필수 범위가 아니라 넣지 않습니다. 수업용 MVP이고, 약관 문서를 만들지 않습니다.
- 아이디는 만들지 않습니다. 테이블에 아이디 칸이 없고, 로그인은 이메일로 합니다.
- 소셜 로그인은 구글 하나만 둡니다. 페이스북은 두지 않습니다. 이유는 `docs/decisions/2026-11-23-social-login.md`.
- 역할은 가입 화면이 아니라, 첫 로그인 다음 화면 `/onboarding/role` 에서 고릅니다. 이건 팀 약속(`docs/TEAM.md`)입니다.

## 로그인 진입

공개 로그인 화면의 입력 순서:

1. 아이디 또는 이메일
2. 비밀번호 (보기/숨기기 버튼이 있음)
3. 로그인 상태 유지 체크
4. 비밀번호 찾기
5. 로그인 버튼
6. 또는 구글 / 페이스북
7. 계정이 없으면 회원가입으로 이동

WorkBridge에 가져갈 흐름:

- 이메일 + 비밀번호만 받습니다.
- 로그인 상태 유지는 체크박스로 만들지 않습니다. 브라우저 쿠키로 세션을 유지하고, 로그아웃을 누를 때까지 이어집니다. 이미 `src/proxy.ts` 가 매 요청마다 세션을 갱신합니다.
- 비밀번호 찾기는 이번 주 범위에 없습니다. 목·금에 시간이 남으면 다시 검토합니다.

## 공개 프로필

파트너 **목록**은 로그인 없이 열렸습니다. 카드 한 장에 아래가 보였습니다.

- 프로필 이미지
- 이름 (일부만 보이고 나머지는 가림)
- 활동 가능 여부
- 직종 (개발, 디자인, 기획)
- 개인/팀/사업자 형태
- 한 줄 소개
- 기술 태그
- 별점과 평가 개수
- 계약한 프로젝트 수
- 포트폴리오 수
- 신원·연락처 인증 표시

목록에는 검색, 등급/형태/직종/지역 필터, 정렬이 있습니다. 이 목록·필터는 2번 담당이라 1번이 만들지 않습니다.

카드를 눌러 들어간 프로필 주소 `/partners/p/{아이디}/` 는 **302로 로그인 화면에 연결**되었습니다. 로그인하지 않고 멈췄습니다. 그래서 프로필 상세에 어떤 칸이 더 있는지는 모릅니다.

WorkBridge는 팀 약속과 다릅니다. 공개 프로필 `/users/[id]` 는 로그인 없이 봅니다.

목록 카드에서만 참고해, 공개 프로필에 둘 정보는 다음으로 줄입니다.

- 이미지, 이름, 역할, 소개
- 프리랜서면 분야, 기술, 경력, 시간당 금액, 포트폴리오 링크
- 의뢰인이면 회사 이름, 업종, 웹사이트
- 평균 별점과 리뷰 목록 자리는 비워 두고 5번 컴포넌트를 끼웁니다

이름은 가리지 않습니다. 회원이 프로필에 적은 이름을 그대로 보여 줍니다. 이메일, 활동 가능 여부, 사업자 형태, 인증 배지는 테이블에 없는 항목이라 만들지 않습니다.

## 1번이 이번 주에 만들지 않는 것

- 홈, 프로젝트 목록, 파트너 검색 필터 (2번)
- 로그인 후 화면 전체 (분석하지 않음)
- 위시켓의 다른 서비스, 스토어, 엔터프라이즈, 사례 검색 AI
- 페이스북 로그인, 별도 아이디, 비밀번호 찾기
